= How to become a technical writer step by step
== Avoid these common mistakes:
* **Overuse of passive voice:** Mainly aim for the active voice to make your documentation more direct and clear.
* Self-referential text: Avoid meta-phrases like "This document describes..." or "In this section, I will show..."
* Anthropomorphism: Do not attribute human emotions or behaviors to software (avoiding phrases like "the program became confused").
* Inconsistent formatting: Watch out for formatting consistency.
* Tutorial vs. Technical writing: Differ educational tutorial and professional tech writing.
* Avoid colorful analogies
* Avoid informal slang and curse words
* Pronoun & Tone : Avoid first-person plural or conversational phrasing like "Let's use...". Use direct, imperative instructions, 2nd person.
* State the objective: Reverse the sentence structure. For example: "use command XY to [achieve goal]" could be better structured as "To [achieve goal], use command XY.

== Follow these human attributes (Soft skills):
* Be open-minded
* Be accurate
* Write briefly
* Write in begginer friendly style
* Be flexible and adaptable
* Have teamwork spirit
* Be communicative
* seek guidence from others

== Objectives of technical witing style:
* Accessibility: Comprehensive for all users
* Readability: for users fast understanding of the text
* Minimalism: reduction of fluff
* Modularity: break down into small blocks (multiple parts)
* Reusability: Reuse of steps for future purposes
